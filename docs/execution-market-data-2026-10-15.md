# Данные для модели исполнения — 15 октября 2026

Первый законченный слой пункта 3: наблюдаемые рыночные данные для будущего расчёта
fills. Пункт 3 целиком остаётся открытым. Действующие сделки, sizing, комиссии,
SL/TP и trailing используют прежние правила execution 0.5.0. Funding выключен.

## Сохраняемые данные

- WebSocket `orderbook.1` даёт лучшую bid/ask и доступное количество каждой стороны.
  Это один уровень; глубина за ним неизвестна. Snapshot-only обработка соответствует
  [контракту Bybit](https://bybit-exchange.github.io/docs/v5/websocket/public/orderbook).
- publicTrade сохраняет точный объём, сторону taker, флаги block/RPI. Отсутствующий
  флаг остаётся неизвестным (`null`). Формат полей:
  [Bybit public trade](https://bybit-exchange.github.io/docs/v5/websocket/public/trade).
- `observedAt` сделки — matching time `T`, стакана — `cts`; `receivedAt` фиксируется
  при получении сообщения, до записи в БД. Для стакана сохранены update ID и sequence.
- Из ограниченной истории соединения выбирается последний уже полученный снимок,
  у которого `cts <= T` и время получения не позже получения сделки. Более поздний
  стакан не подставляется назад. При отсутствии подходящего снимка сохраняется `null`.
  Максимум 512 снимков на символ; неизвестная более ранняя история не реконструируется.
- Новое соединение, удаление подписки, пустой snapshot и service restart (`u=1`)
  очищают соответствующую историю. Повтор heartbeat разрешён; update IDs могут
  пропускать значения. Регресс последовательности, crossed book, неверный формат,
  неподходящий topic или небезопасная точность ID делают стакан неизвестным до
  следующего корректного snapshot. В worker для этого отдельный обработчик ошибок:
  publicTrade продолжает работать; неверные данные самого publicTrade или сетевой
  разрыв обрабатываются прежним reconnect/recovery.

Стакан прикреплён к публичным сделкам. Все изменения стакана отдельными событиями
в БД не пишутся; этот слой не доказывает состояние очереди или исполнение заявки
между двумя publicTrade. Публичный стакан также не включает RPI-заявки.

## Хранение и воспроизведение

Nullable `MarketPriceEvent.executionData` — компактный версионированный JSON tuple:

```text
[1, tradeQuantity, takerSide, blockTrade|null, rpiTrade|null,
 [bidPrice,bidQuantity,askPrice,askQuantity,bookObservedMs,bookReceivedMs,updateId,sequence]|null]
```

Decimal и IDs передаются строками без преобразования в `number`. Старые записи
остаются `null`. Повтор ID не меняет первый снимок и время получения; конфликт
цены, matching time или торговых реквизитов откатывает весь batch. Стакан может
отличаться при повторной доставке после reconnect: исходный снимок сохраняется.

Архив v2 добавляет tuple седьмым полем события; reader принимает прежний v1.
Checksum, причинность стакана и полнота событий проверяются. Hot/cold конфликт
учитывает также event key и новые данные. Архивация/retention прежние: непрочитанный
хвост остаётся горячим, нужная истории позиции сохраняется до 30 дней после закрытия.
Версии расчёта execution/validation не меняются: формулы fills здесь не изменены.

## Проверка

- 296 тестов прошли, включая отдельную PostgreSQL со всеми 37 миграциями; пропусков нет.
- Проверены обе временные границы причинности, skipped/repeated IDs, restart,
  reconnect, отсутствие стакана, crossed/zero quotes, некорректные сообщения,
  точные Decimal/большие IDs, rollback конфликтного batch и сохранение первого снимка.
- Некорректный стакан между двумя корректными снимками не обрывает поток цен;
  промежуточный trade получает неизвестную ликвидность, следующий — новый снимок.
- DB regression проводит закрытую позицию через архив v2, удаление hot events,
  повторное чтение и денежный replay. Отдельно проверяется чтение v1.

- Независимая read-only подписка на реальный рынок, 25 секунд: BTC 870, ETH 814,
  DOGE 392 публичных сделки; у всех причинный стакан возрастом до 1 секунды.
  Одно соединение, ошибок нет. Это короткая проверка протокола, не нагрузочный тест.
- На 870 BTC событиях архив занимает 30 836 байт против 25 148 без market data:
  дополнительно 6,54 байта/событие после gzip. Это измерение конкретной выборки.

## Диагностика

```bash
pnpm runtime:market-data
```

Команда читает последние 20 000 событий в read-only repeatable-read транзакции.
По каждому символу показывает отсутствие новых данных/стакана, свежесть, нарушения
причинности, флаги block/RPI, p50/p95/max спреда и задержек, средний размер JSONB,
размер горячего журнала и архива. Некорректный tuple или стакан из будущего дают
ненулевой exit code. Порог свежести 1000 мс здесь диагностический;
он ещё не является новым запретом входа. Задержки не приравниваются к задержке
реального исполнения. Сравнение двух часов может показывать clock skew.
