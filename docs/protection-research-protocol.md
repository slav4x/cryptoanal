# Протокол исследования защиты v1

До расчёта результатов фиксируются `cryptoanal-protection-study@1`, параметры и
пороги в `packages/application/src/protection-study.ts`. Hash протокола, hash файлов
реализации и Git revision сохраняются в каждом результате. Команда:

```bash
pnpm runtime:research-protection development var/analysis/protection-study-2026-10-16.json
```

Это локальная read-only команда: все подключения PostgreSQL получают
`default_transaction_read_only=on`, значение проверяется до чтения. Существующий
файл не перезаписывается. Новых зависимостей и изменений runtime нет.

## Набор вариантов

Меняется только дополнительная защита прибыли. Собственные SL/TP, break-even,
trailing, signal/time exits и account risk каждой стратегии сохраняются.

| Вариант               | Безубыток                 | Активация trailing | Расстояние trailing |
| --------------------- | ------------------------- | ------------------ | ------------------- |
| current               | 0,5R                      | 1R                 | 0,5R                |
| later-break-even      | 0,75R                     | 1R                 | 0,5R                |
| later-trailing        | 0,5R                      | 1,5R               | 0,5R                |
| wider-trailing        | 0,5R                      | 1,5R               | 0,75R               |
| tighter-trailing      | 0,5R                      | 1R                 | 0,35R               |
| strategy-only-control | без дополнительной защиты | —                  | —                   |

Последний вариант — диагностический контроль; он не участвует в выборе замены.
Если параметры действующей закреплённой защиты отличаются от current, исследование
останавливается для этой стратегии, вместо молчаливой подмены исходной политики.

У исторических baseline время включения защиты может быть позже конца набора
свечей. Каждый исследовательский вариант включает защиту с начала своего окна,
только для новых входов, без переноса прежнего пика. Исходная политика и её hash
сохраняются отдельно. Это контрфактический сценарий, а не пересчёт старой validation.

## Время, выбор и стоимость

После общего warmup остаются три последовательных периода: 60% обучение,
20% проверка, 20% финальный holdout. Каждый символ должен иметь те же непрерывные
временные отметки. Индикаторы используют сохранённую предшествующую историю;
позднейшие цены не участвуют в ранних значениях. На границах позиции закрываются
как `end-of-data`, капитал и дневные состояния каждого окна начинаются заново.
Число таких граничных закрытий выводится отдельно.

Победитель выбирается только по обучению: минимум 40 сделок у current и кандидата,
наибольший net PnL среди улучшений с просадкой не выше current. При отсутствии
подходящей замены остаётся current. Порядок при равенстве детерминирован именем.
Финальный кандидат фиксируется до просмотра следующих периодов; при провале
проверки не выбирается следующий по её результату вариант.

Walk-forward: три тестовых окна между 40% и 80% истории. Перед каждым выбор
повторяется на расширяющемся прошлом, без holdout. Этот результат оценивает процедуру
выбора, а не выдаётся за три независимых подтверждения одной и той же настройки.
Периоды walk-forward пересекаются с development, но не с финальным holdout.

Порог исследовательского кандидата: минимум 20 сделок на validation, 30 на holdout
и 20 в каждом walk-forward test, для current и выбранного варианта. Чистый прирост
на validation и holdout — не менее 0,5% начального капитала, результат кандидата
положителен, просадка не хуже current. Минимум два walk-forward теста дают улучшение
при не большей просадке. Это заранее заданные фильтры исследования, не доказательство
статистической значимости и не оптимизация всех параметров стратегии.

Net PnL уже включает комиссии, проскальзывание в ценах и сохранённый funding;
проскальзывание повторно не вычитается. Используется общий engine с закреплённой
OHLC adverse-first политикой, исходными instrument rules и funding snapshot с
проверкой hashes. Суммы разных виртуальных аккаунтов не выдаются за общий портфель.
Просадка рассчитывается на уровне виртуального аккаунта стратегии; результаты
по символам и сторонам являются атрибуцией сделок этого аккаунта.

Для преждевременных выходов сравниваются только сделки с теми же символом, стороной
и временем входа. Если кандидат вышел раньше current и получил меньший net PnL на
единицу объёма, это считается преждевременным выходом относительно current.
Нормирование не позволяет изменению размера позиции подменять качество выхода.
Покрытие сопоставленными входами выводится явно; требуется не менее 50%, а доля
таких выходов — не более 5%. Это диагностический контрфактический показатель:
поздняя прибыль current не объявляется доступным биржевым fill кандидата.

## Наблюдаемые MFE/MAE

Для закрытой сделки считаются максимальные благоприятное и неблагоприятное
движения LastPrice от цены входа в единицах первоначального риска, первое время
пика/неблагоприятного экстремума, максимальная просадка цены от пика, откат к
средней цене выхода и длительность удержания. R восстанавливается из исходного
конфига и закреплённых шагов инструмента; текущий перемещённый стоп не используется.
Откат в R — ценовой показатель, он не подменяет денежный результат частичных fills.
Время пика неизвестно, если положительного движения среди наблюдений не было.

Перед расчётом проверяется исходный trace replay и checksums. Полным считается
только подтверждённый непрерывный путь от входа. Отсутствующее начало, stream change,
восстановление OHLC, недостающий хвост, несовпадение replay и обратный ход времени
источника отражаются отдельными причинами. Наблюдаемые экстремумы частичного пути
являются нижними границами; при отсутствии trace значения остаются неизвестными.
Цена после фактического закрытия не улучшает MFE уже завершённой сделки.

Результаты разделены по strategy version, execution run, символу, стороне,
таймфрейму, execution/exit/funding/recovery model и hash execution policy.
Группы разных правил не объединяются для вывода об оптимальности параметров.
Открытые позиции не считаются завершёнными независимыми наблюдениями.

## Решение и применение

Даже успешный свечной кандидат требует независимой проверки на данных, которые
не использовались для прежнего выбора стратегии, и минимум 30 полных наблюдений
именно кандидатской политики с проверяемой моделью исполнения. Сохранённые
исторические наборы уже участвовали в проверках текущих стратегий; их holdout
является ретроспективным. Данные LastPrice/L1, funding и instrument scenario имеют
разную степень точности и не объявляются взаимозаменяемыми.

Команда сохраняет immutable snapshot исследования: исходную версию стратегии,
исходную validation и policy, исследуемые параметры/окна/стоимость, выбранный по
обучению вариант, holdout и walk-forward, причины решения и `applied: false`.
Текущие принятые параметры привязаны к существующим strategy version и validation
snapshot. При недостатке доказательств новая версия стратегии не создаётся.
Применение иной настройки потребует отдельной версии, validation snapshot и обычного
процесса допуска. Экспорт JSON не является запросом к работающему движку.
