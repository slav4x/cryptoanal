## Правила и параметры

`exit.signalExitModel: "family-invalidation@1"` явно выбирает новые правила.
В этом режиме `exit.exitOnSignalReversal` включает сигнальный выход для любого
семейства. Все условия оцениваются по закрытой свече после её подтверждения;
фильтры RSI, объёма, времени торговли и разрешённой стороны ограничивают входы,
но не мешают выходу.

| Семейство      | Long                                 | Short                               |
| -------------- | ------------------------------------ | ----------------------------------- |
| EMA            | Обратное пересечение fast ниже slow  | Обратное пересечение fast выше slow |
| Breakout       | Close ≤ уровня исходного пробоя high | Close ≥ уровня исходного пробоя low |
| Momentum       | Momentum ≤ 0                         | Momentum ≥ 0                        |
| Mean-reversion | Z-score ≥ 0                          | Z-score ≤ 0                         |

Уровень breakout берётся из сигнальной свечи, исключающей саму свечу пробоя
из предшествующего диапазона. Он сохраняется в pending signal, snapshot заявки,
позиции и trace. Позднейший скользящий high/low не заменяет исходный уровень.
Для momentum используется прежний lookback; падение ниже порога входа при всё ещё
положительном long/отрицательном short импульсе само по себе не является отменой.
Отмена идеи закрывает объём, но не создаёт обратную позицию. Новый вход требует
самостоятельного сигнала, разрешённого направления, свежей цены и account risk gate.

`exit.maxHoldingMinutes` — необязательное целое число 1…525600. Отсутствие поля
означает отсутствие ограничения. Срок равен `Position.openedAt + minutes * 60000`:
от `observedAt` ценового события, исполнившего вход DRY_RUN, включая частичный вход, а не от
обнаружения сигнала, отправки заявки, перезапуска или начала календарной свечи.
После частичных выходов первоначальное `openedAt` и срок сохраняются.
Новый вход и новые fills биржи Demo/Live этим изменением не реализованы.

В редакторе новой стратегии выбраны новые правила; сигнальный выход выключен,
срок пустой. При открытии существующей версии сохраняются её прежний режим и
отсутствующий срок. Переход выполняется явно в новой версии стратегии с проверкой
и обычным запуском. Подбор значений срока и включение новых правил на действующих
34 запусках автоматически не выполняются.

## Совместимость и порядок

Без `signalExitModel` остаются прежние сигнальные правила: EMA только при включённом
флаге, mean-reversion всегда при возврате к среднему, breakout/momentum без сигнального
закрытия. Можно добавить только срок и сохранить прежнюю сигнальную модель.
У старых позиций `positionExitPolicy = NULL`; их правила, исторические пики,
Trade и результаты завершённых validation не переписываются.

Новая политика создаётся при входе и проверяется относительно immutable snapshot
заявки; подмена срока или уровня при сохранении fill отклоняется. Перезапуск читает
политику позиции, а не новые значения настроек worker. Ledger сверяет её привязки
к заявке, trace и конфигурации стратегии. Старые trace 0.4…0.12 остаются читаемыми
в рамках ранее поддерживавшихся моделей. Исходные golden fixtures и их результаты
сохраняются; проверка явно допускает совместимую пару validation 0.15.1/replay 1.9.1
только для конфигураций без новых правил и сравнивает весь результат нового движка
с прежним эталоном.

Для одного ценового события порядок таков:

1. Уже зафиксированное намерение закрытия продолжает исполняться до нулевого остатка.
2. Достигнутый SL/trailing или TP проверяется по известной цене.
3. Истёкший срок закрывает по этой цене без ожидания свечной истории.
4. Доступный подтверждённый сигнал закрывает по исполнимой цене события.
5. При отсутствии выхода обновляется защита позиции.

SL/trailing выбирается по более сильному защитному уровню; равные уровни дают SL.
Сигнальный выход никогда не исполняется задним числом по close свечи после поздней
finality. Сохраняются `availableAt`, цена/время подходящего события и причина
`ema-reversal`, `breakout-invalidated`, `momentum-invalidated` или `mean-return`.
Общая причина сделки — `signal-exit`, для срока — `holding-timeout`.

Account safety проверяется независимо: kill switch и дневной предел прекращают
новые входы и запрашивают принудительное закрытие. При конкуренции путей первое
успешное сохранение под общими locks/CAS фиксирует причину; второй путь не заменяет
уже принятое намерение и не создаёт вторую сделку. В свечной модели account safety
по-прежнему проверяется на её явно заданных этапах, без притворной биржевой точности.

## Цена, история и ликвидность

Без цены после срока не создаётся фиктивный fill на границе. При непрерывном журнале
берётся первое известное событие на сроке или позже. Отдельный приоритетный путь
проверяет срок с интервалом опроса по умолчанию 100 мс, даже когда восстановление
истории заблокировано.
При пропуске истории он может запросить выход по свежей известной цене; такой trace
остаётся incomplete, как и прочие выходы через неподтверждённый разрыв.

Health различает `RUNTIME_HOLDING_PRICE_UNAVAILABLE` (нет подходящей свежей цены)
и `RUNTIME_HOLDING_EXIT_OVERDUE` (срок истёк, цена есть, выход ещё не завершён).
Проверка выполняется после допуска, равного закреплённому `maxQuoteAgeMs`;
это допуск диагностики, а не продление торгового срока.

Для позиций с L1 IOC тайм-аут фиксирует намерение, а не гарантирует полный fill
в эту миллисекунду. Сохраняются фактическая ликвидность, частичные исполнения,
повторы/TTL и причины ожидания. Нехватка цены, стакана, funding или встречного
объёма может задерживать полное закрытие. В версии с fixed slippage timeout receipt
также проверяет исходную политику и фактическое ценовое событие.

OHLC не даёт цену внутри свечи в произвольную минуту. При сроке на её открытии
проверяется open до будущих экстремумов. Для срока внутри свечи применяется
существующий adverse-first сценарий и закрытие по close, если защита/TP не закрыли
позицию раньше по модели. Это может дать опоздание до одной свечи; пропуски свечей
могут увеличить его. Runtime по public trades и OHLC сравниваются с этим явным
ограничением, без заявления об одинаковом времени или доходности.
