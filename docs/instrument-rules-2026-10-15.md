# Биржевые шаги и размеры — 15 октября 2026

Выполнен пункт 2 рабочего списка. Новые входы и защитные уровни нормализуются
общим application-расчётом в runtime, validation и replay. Новые зависимости не нужны.
Версии: execution 0.5.0, validation 0.13.0, candle replay 1.7.0.

## Правила

| Значение                  | Long / buy           | Short / sell         |
| ------------------------- | -------------------- | -------------------- |
| Количество                | Вниз по `qtyStep`    | Вниз по `qtyStep`    |
| Лимит входа               | Вниз по `tickSize`   | Вверх по `tickSize`  |
| Моделируемый market-вход  | Вверх после slippage | Вниз после slippage  |
| SL, TP и защитные уровни  | Вверх                | Вниз                 |
| Моделируемый market-выход | Вниз после slippage  | Вверх после slippage |

Лимит проверяется на касание уже после округления. Схлопнувшиеся SL/TP, выход
за диапазон цены, нулевое количество и нарушение минимумов блокируют вход.
Размер ограничивается риск-бюджетом, экспозицией с комиссией и биржевыми максимумами.
Количество не увеличивается ради прохождения минимума.

Кратность и округления считаются десятичными дробями на BigInt, включая деление
для безубытка. Не представимые существующим числовым движком значения отклоняются,
а не сохраняются с потерей нужных разрядов. Комиссия и entry slippage масштабируются
вместе с количеством; риск проверяется повторно под account lock.

R новых позиций — расстояние до исходного SL после округления. Границы активации
сравниваются точно. Дополнительный trailing считается в абсолютной цене из R,
без промежуточного перевода в проценты. Динамический trailing короче тика получает
ближайший допустимый уровень за ценой; прежняя защита не ослабляется. Безубыток
покрывает комиссии и округление моделируемого выхода.

Источник ограничений — [Bybit Instruments Info](https://bybit-exchange.github.io/docs/v5/market/instrument).
Добавлены `maxOrderQty`, `maxMktOrderQty`, `minPrice`, `maxPrice`; существующие
tick/quantity/minimum filters сохранены. Смысл market/limit параметров сверялся с
[Bybit Place Order](https://bybit-exchange.github.io/docs/v5/order/create-order).

До реализации частичных fills размер одной DRY_RUN позиции дополнительно ограничен
меньшим из limit/market максимумов, чтобы единственный защитный market-выход
помещался в одну заявку. Разделение объёма относится к пункту 3.

## Снимки и конкурентные изменения

Обязательные metadata старше часа, отсутствующие/некорректные поля или timestamp
из будущего блокируют вход с отдельной причиной. Перед записью проверяются
актуальность, совпадение snapshot и действующих ограничений, шаги, минимумы,
максимумы и расположение SL/TP. Инструмент удерживается `FOR SHARE` до commit:
параллельное обновление его параметров ждёт окончания допущенного входа.

Позиция и execution trace сохраняют одинаковый snapshot. Начальные Decimal-значения
trace берутся из фактически записанной позиции, включая округлённую точность комиссии.
После restart источник расчёта — сохранённые правила, а не текущая таблица инструментов.
Старые открытые позиции без snapshot продолжают прежнюю модель до закрытия.

Новый validation один раз закрепляет правила с checksum в `ValidationRun.executionRules`.
Retry использует их повторно; изменение сегодняшних metadata не меняет результат.
Истории прежних правил биржи нет: применение фиксированного снимка к прошлому периоду
явно обозначено как `fixed-snapshot-scenario` в provenance и интерфейсе проверки.
Это допущение отдельно от формальных gates результата. Прежние validation не переписаны.
