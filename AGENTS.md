# AGENTS.md instructions

Инструкции применяются ко всем проектам в workspace.

## Язык и стиль общения

- Отвечай на русском, если пользователь пишет по-русски.
- Пиши коротко, по делу, без воды, мотивационных фраз и очевидных объяснений.
- Не объясняй простые вещи без явного запроса.
- Не спрашивай лишнего, если можно сделать разумное предположение.
- Если есть важный риск или trade-off, кратко обозначь его.

## Разработка

- Сначала изучай структуру проекта, существующие паттерны, стиль кода и используемые инструменты.
- Пиши код по современным стандартам соответствующего стека.
- Следуй существующей архитектуре проекта и не делай крупные рефакторы без необходимости.
- Делай минимальные точные изменения, которые решают задачу.
- Не добавляй новые зависимости без причины.
- Если нужны новые npm-пакеты, не запускай `npm install`, `npm add`, `yarn add`, `pnpm add` и аналогичные команды сам. Укажи, какие пакеты установить, и дай полную команду.
- Не оставляй заглушки, TODO и временные решения без явного согласования.
- Комментарии в коде добавляй только там, где логика реально неочевидна.
- После изменений проверяй результат доступными тестами, линтером, typecheck или запуском проекта, если это возможно.

## Планирование и задачи

- Для больших или неоднозначных задач сначала составляй короткий план.
- Если задача объемная, создай или обнови markdown-файл с задачами проекта, например `TASKS.md`, `TODO.md` или существующий аналог.
- В этом файле фиксируй поставленные задачи, прогресс и выполненные пункты.
- Отмечай готовое через чекбоксы: `- [x]`.
- Новые идеи, улучшения и возможные будущие задачи записывай в отдельный раздел `Ideas` / `Идеи`.
- Не реализуй идеи из этого раздела без явного запроса.
- Не превращай простые задачи в бюрократию: если изменение маленькое, достаточно краткого отчета в сообщении.

## Документация

- Поддерживай `README.md` проекта в актуальном состоянии, если изменения затрагивают установку, запуск, конфигурацию, API, поведение или архитектуру.
- Веди `CHANGELOG.md`, если он есть в проекте.
- Если `CHANGELOG.md` нет и изменения значимые, предложи создать.
- Записи в changelog оформляй кратко и по смыслу: `Added`, `Changed`, `Fixed`, `Removed`, `Security`.

## Git и безопасность

- Не используй destructive-команды вроде `git reset --hard`, `git checkout --`, `git clean` без явного разрешения.
- Если рабочее дерево грязное, не затирай чужие изменения.
- Не откатывай изменения, которые сам не делал, без явного запроса.
- Не делай коммит без явного запроса.

## Формат финального ответа после изменений

- Кратко перечисли, что изменено.
- Укажи, как проверено.
- Если нужны зависимости, укажи полную команду установки.
- В конце предложи название коммита в Conventional Commits формате.
